**实验背景提炼 — CRC 患者交流模拟用**

将药物临床试验登记与信息公示平台（CDE）结构化登记资料，整理成患者交流模拟可用的研究背景摘要。

---

**一、任务目标**

从输入的 CDE JSON 中提炼患者沟通场景需要的事实，输出固定 JSON Schema。表述面向 CRC 训练，用患者能听懂的说法概括「研究设计」「给药安排」，但不得改写入排标准原文。

---

**二、必须提取的字段**

| 字段 | 提取要点 |
|:---|:---|
| 研究登记号 | `basic_info.registration_no` |
| 药物 | 通用名/制剂名（如片剂、注射液），勿编造商品名 |
| 疾病 | 适应症原文要点 |
| 研究设计 | 合并期别、设计类型、随机化、盲法、单臂/平行等已给出信息 |
| 给药安排 | 仅据 `arms` 中用法、频次、疗程等已写明内容整理；未写到院安排则不写 |
| 入选标准 | **逐条完整保留原文**，顺序与输入一致 |
| 排除标准 | **逐条完整保留原文**，顺序与输入一致 |
| 其他已知信息 | 患者沟通相关且资料已出现的事实（如保险有无、年龄性别范围、是否健康受试者、招募状态、研究目的要点、中心数量等） |
| 未提供的信息 | 沟通常问但资料未给出的项，明确列出 |

---

**三、硬性规则**

1. **只依据输入资料**：未出现的内容不得猜测、补全或「合理推断」。
2. **入排标准逐条保留原文**：不得改写、合并、删减或概括；不得为条目添加编号前缀以外的加工（若原文无编号则保持原文）。
3. **不添加 ID / 来源标注**：输出字段值中不要写 `source`、`source_id`、条目 ID、引用脚注。
4. **时间概念不得混用**：
   - 给药间隔 ≠ 到院/访视间隔（有给药频次不等于已知随访日程）
   - 终点评估时间窗 ≠ 研究总时长（如「首次给药后 28 天」「整个研究过程」不能当成总时长）
5. **未提供则列入「未提供的信息」**：常见缺口包括完整到院安排、单次访视耗时、研究总时长、具体费用与补贴、安慰剂比例细节（若未写）、洗脱/导入细节（若未写）等——以实际缺失为准，不要机械照抄模板。
6. **「其他已知信息」只写已证实事实**：可用短句；不确定则不要写入该项，改列入未提供。

---

**四、输出要求**

- 只输出一个 JSON 对象，不要 markdown 代码块，不要其它说明。
- 字段名与 Schema 完全一致（中文键名）。
- `入选标准`、`排除标准`、`其他已知信息`、`未提供的信息` 均为字符串数组。
